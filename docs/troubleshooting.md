# トラブルシューティングと FAQ

よくある問題を、表示されるメッセージごとにまとめています。メッセージの一部でこのページを検索してください。

## 起動とインストール

### `uv: command not found`

uv が入っていないか、`PATH` に入っていません。[インストール](getting-started/install.md#per-os) の手順で入れてから、新しいターミナルを開いてください（公式のインストーラは `~/.local/bin` に入れます）。

### `ModuleNotFoundError: No module named 'klayout'`（または `gdsfactory`、`fastapi`）

依存パッケージが `.venv` に入っていません。リポジトリのディレクトリで `uv sync` を実行してください。`git pull` などで `pyproject.toml` や `uv.lock` が変わったときも、`uv sync` で入れ直します。

### `error: externally-managed-environment`

`pip install` をシステムの Python に対して実行すると出ます。このプロジェクトでは pip は使わず、`uv sync` で `.venv` に入れてください。

### `address already in use`

ポート 8000（API サーバ）がほかのプログラムに使われています。使っているプログラムを止めるか、前に起動した `npm run dev` が残っていないか確かめてください。ポート 5173 が使われているときは、Vite が 5174 などの空いたポートで起動します。表示されたアドレスを開いてください。

## シミュレーション

### ngspice が見つからない { #ngspice-not-found }

コンソールに次のように出ます。

```text
ERROR: サーバ側シミュレータを利用できません — ngspice not found. Install it ...
```

ngspice を入れるか（[インストール](getting-started/install.md#requirements)）、場所を `AGILEX_NGSPICE` で指定して API サーバを起動し直してください。

```bash
AGILEX_NGSPICE=/path/to/ngspice npm run dev
```

API サーバが探した結果は `curl http://127.0.0.1:8000/api/simulate/status` で確かめられます。

### `シミュレーション API に接続できません`

API サーバが動いていません。`npm run dev` を実行したターミナルに、`api` のエラーが出ていないか確かめてください。画面だけを `npm run dev:vite` で起動したときは、別のターミナルで `npm run dev:api` を実行します。

起動直後は API サーバの準備が遅れることがあります。画面は 30 秒ほど自動で接続し直します。

### `simulation timed out after 120 s`

シミュレーションが 120 秒で終わりませんでした。`.tran` の時間範囲を短くするか、最大刻み幅を大きくしてください。長い計算が必要なときは、`AGILEX_SIM_TIMEOUT`（秒）を大きくして API サーバを起動します。

### 波形が粗い

ngspice の結果が 8000 点より多いと、表示用に間引きます。見たい範囲だけを `.tran` で計算するか、`AGILEX_SIM_MAX_POINTS` を大きくしてください。点数を増やすとブラウザへの転送量も増えます。

### `ERROR: unknown subckt: ...`

`INV` などのサブサーキットの定義がネットリストにありません。ネットリストを手で書いたときは、[プリアンブル](guide/netlist.md#preamble) を先頭に入れてください。

### `ERROR: No plottable signals in simulation result`

表示できる信号がありません。`.op` だけの解析か、すべての信号が一定の値です。`.tran` か `.ac` を使ってください。

## レイアウト

### `レイアウトを表示できません`

レイアウトの画像を API サーバから取得できませんでした。API サーバが動いているか、`npm run dev` を実行したターミナルにエラーが出ていないか確かめてください。

### `combined.gds がありません`

まだ一度もレイアウトを同期していないので、ダウンロードするファイルがありません。**レイアウトを同期** を押してください。

### レイアウトの一部が表示されない、ぼやけたまま

拡大したときは、その倍率のタイルを API サーバに描かせて読み込みます。読み込み中は粗いタイルで仮に埋めるので、少し待ってください。
読み込みに失敗したタイルは、次に表示を動かしたときに読み直します。

### `レイアウト同期失敗 (HTTP 422): ...`

配置・配線が、どの試行でも成功しませんでした。理由ごとの対処は [レイアウト: 同期に失敗したとき](guide/layout.md#sync-errors) を参照してください。

### レイアウトタブに **未同期** と出たまま

ネットリストを変えたあと、レイアウトを作り直していません。**レイアウトを同期** を押してください。

### `ポップアップがブロックされました`

**印刷** と **新しいタブで開く** は、新しいウィンドウを開きます。ブラウザでこのサイトのポップアップを許可してください。

## FAQ

### 実際のチップと同じ特性でシミュレーションできますか？

いいえ。トランジスタは LEVEL=1 の簡易モデルで、論理動作とおおまかな遅延を確かめるためのものです。

### ゲートアレイ以外のレイアウトや、ほかのプロセスに使えますか？

いいえ。配置・配線は [Agile-X](https://www.agile-x.t.u-tokyo.ac.jp/) のゲートアレイ（`base.gds`）専用です。ゲートアレイの部品を使わない回路は、シミュレーションだけに使えます。

### ngspice がなくても使えますか？

ブロック図、ネットリスト、レイアウトは使えます。シミュレーションだけができません。

### インターネットに公開してもよいですか？

おすすめしません。API サーバには認証がなく、受け取ったネットリストで ngspice を実行します。公開するときは、認証と、ngspice を動かす環境の隔離を用意してください。

### 不具合はどこに報告すればよいですか？

[GitHub の Issues](https://github.com/kadomoto-lab/agile-x-studio/issues) に報告してください。次の情報があると調べやすくなります。

- 何をして、何が起きて、本来どうなるはずだったか
- ネットリスト（ネットリストタブの内容）
- コンソールの表示と、`npm run dev` を実行したターミナルの出力
- OS、Node.js・Python・ngspice のバージョン
